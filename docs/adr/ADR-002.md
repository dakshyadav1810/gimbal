# ADR-002: Spec, grounding, healing and repair

**Status:** Accepted

## Context

Intent (what a user is trying to do) rarely changes. Selectors and layout change constantly. An agent can describe intent without seeing the page, but it cannot produce selectors that survive.

## Decision

Keep intent and page anchors in separate artifacts and combine them deterministically:

```
spec.json        intent, semantics, assertions. DOM-blind. Written by the agent.
grounded.json    spec + the element found on the live page + evidence. Written by grounding.
candidates.json  what grounding considered, privacy-filtered.
repairs.json     heals and abstentions with their decisions.
```

- **Grounding** resolves each target against the live page with a multi-signal resolver (affordance filter, semantics, context, structure, index tie-break) and stores the winner.
- **Healing** re-resolves one step at run time when its selector no longer matches. It is stricter than grounding: it requires a clear lead over the runner-up, stays inside the original container, and respects earlier rejections.
- A heal is **verified after acting** against the step's outcome or its recorded effect, and only then recorded.
- A **repair** is the reviewable record of a heal or of an abstention. Accepting it folds the new selector into `grounded.json`.

## Consequences

- The agent never sees or writes a selector.
- Every change to a test's anchors is a file diff.
- A wrong heal is caught only if the step has something to check. Gimbal warns when a click has no outcome.
