# ADR-001: No generative model at run time

**Status:** Accepted

## Context

Letting a model repair failing tests at run time is tempting. It also makes runs non-deterministic, slow and costly, makes failures hard to reproduce, and ties every run to an external service being available.

## Decision

**At run time, Gimbal calls no generative model and no external model service.**

Models take part only in authoring and in explicit maintenance, and those happen in the developer's own coding agent, not inside Gimbal. Gimbal has no model client, no API key and no provider setting.

A local, frozen embedding model is allowed at run time. It is a fixed function of its pinned weights and its input: the same text gives the same vector, offline, with no call out. The configuration pins an exact model revision, and a test grounded with one revision is refused under another.

The runtime order is: cached selector, stored selector, a verified earlier proposal, a bounded deterministic heal. If none is trustworthy, the step is marked as needing a fix (it abstains) and a person or their agent repairs it.

## Consequences

- Runs are reproducible and cheap, and work offline once the embedding model is downloaded.
- Some UI changes cannot be recovered automatically. That is reported as a repair that is needed, not guessed.
- Anything "smart" must be framed as authoring-time work done by the connected agent.
