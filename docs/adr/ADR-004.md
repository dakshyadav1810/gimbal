# ADR-004: KDG Construction — Deterministic Static Analysis, Next.js-First

**Status:** Accepted
**Date:** 2026-07-27
**Author:** (agent-drafted, Gimbal project)
**Relationship:** Fulfills the deferred item in [ADR-002](./ADR-002.md) ("KDG internal data structure and construction algorithm... in a follow-up ADR", Out of Scope §, Action Item 8). Operationalized in [LLD-011](../lld/LLD-011-kdg.md); product contract in [SPEC-006](../specs/SPEC-006-kdg.md).

## Context

ADR-002 named the KDG (Knowledge/Dependency Graph) as authoring-time and repair-time context — fetched via `getMap`/`getDelta` MCP tools so a connected coding agent can ground its semantic test targets in the app's real structure, and folded into the maintenance-heal repair payload — but explicitly deferred its internal structure and construction algorithm. Since then:

- The project has rebranded (Axiom → Gimbal); this ADR uses the current naming throughout.
- Discussion with the team established the actual constraint driving this ADR: **KDG re-runs must be cheap.** The motivating failure mode is a codebase large enough that an agent re-reading the whole frontend on every authoring or healing pass is unreliable or exceeds its context window. A knowledge graph only earns its construction cost if querying it is cheaper than re-deriving the same facts from source each time — otherwise it is pure overhead on top of what the agent could do by reading the relevant files directly (which, on a small app, it already can, for free).
- The team also fixed the initial platform scope to **Next.js App Router projects only**, deliberately deferring generic React/Vue/Angular support. This is a real simplification, not a nice-to-have: App Router's file-based routing gives route topology directly from the filesystem, with no router-config parsing needed.
- A companion research pass (informal, this session) established the boundary of what static analysis can determine about React/Next.js conditional rendering without executing code: parent/child JSX containment, and *that* a conditional branch exists plus its raw expression, are reliably extractable; resolving a condition through a HOC, custom hook, or context requires following an identifier to its definition (tractable, bounded engineering, not guessing); resolving anything gated by runtime-only data (network-fetched feature flags, request-time middleware state) is not obtainable from source under any static or agentic analysis — the honest ceiling there is "flag it and say where to look," not "know the answer."
- The team also concluded — after directly reasoning about who consumes the KDG and what they do with it — that the KDG's conditional data does **not** need a pre-classified taxonomy (`kind: "role" | "featureFlag" | ...`). The sole consumer is an LLM coding agent, which can interpret a raw condition expression as easily as a taxonomized label. What static analysis cannot resolve should not be guessed at (by a taxonomy or otherwise) — it should point the agent at exactly the file and identifier to look at next, since that is strictly more useful to an agent than an opaque `unknown` and strictly safer than a fabricated classification.

## Decision

The KDG is a **versioned, incrementally-rebuildable structural graph**, constructed entirely by deterministic static analysis of the frontend source (no LLM call anywhere in construction), scoped to Next.js App Router conventions for v1.

1. **Construction is static-analysis-only, using the TypeScript Compiler API** (already a dependency; no new AST-tooling dependency needed for v1). No model call participates in building, updating, or classifying any part of the graph. This preserves the same deterministic-first posture as grounding/resolution (ADR-001/002) — the KDG must never be a second place where Gimbal silently guesses.

2. **Tracked source is discovered by Next.js App Router convention, not configured.** The build walks `app/**/page.tsx`, `layout.tsx`, and `route.ts`, plus each entry file's transitive local imports (stopping at `node_modules`). No glob config is required for v1; this is the smallest scope that gives route topology for free and needs no per-project tuning.

3. **Every conditional branch is captured with three possible resolutions, not a binary known/unknown:**
   - **`resolved`** — the condition is inline or resolves through one safe, traceable hop; store the verbatim raw expression.
   - **`needs_trace`** — the condition is gated behind a HOC, custom hook, or context static analysis can locate but not safely evaluate; store the raw expression **and** a pointer (file path, line, one-line instruction) telling the agent exactly what to look at next.
   - **`unknown`** — the condition depends on runtime-only data (network-fetched flags, middleware) that no static or agentic reading of the repo can resolve; store the raw expression and mark it as such, with no invented classification.

   There is deliberately no `{kind, key, expected}` taxonomy. The agent, not Gimbal, is responsible for interpreting the raw expression text — that interpretation is exactly what an LLM-authoring agent already does well, and a taxonomy would only add a way for Gimbal to be wrong about something it doesn't need to decide.

4. **Construction triggers on-demand, from the `getMap` MCP tool call**, not a background watcher or a separate CLI command for v1. `getMap` first checks a stored per-file content-hash manifest against the tracked source; if nothing has changed, it serves the cached graph immediately; if some files changed, it re-parses only those files and patches the graph (see item 6) before responding.

5. **`getMap` returns a route-scoped subgraph, not the whole app.** `entryUrl` resolves to its `page.tsx`; the response is that route's transitive component subgraph only. This is what actually delivers "cheap enough for a large codebase" on the read side — a graph that returns its entire contents on every call reintroduces the same context-window problem the KDG exists to avoid.

6. **Incremental rebuilds are per-file node replacement.** The manifest diff identifies exactly which tracked files changed; only those are re-parsed, their previously-produced nodes are removed and replaced, and parent/child edges touching the boundary are re-linked. Cost is proportional to files changed, not app size — this is the mechanism that makes "reruns must be cheap" true rather than aspirational.

7. **Persistence is SQLite-only, alongside the existing resolver cache** (`resolution_cache`, `embeddings`) — new tables for graph nodes and the file-hash manifest, in the same `.gimbal/cache.db`. The KDG is regenerable derived state, not a durable authored artifact: deleting `cache.db` costs a rebuild, never data, matching the invariant the project already applies everywhere else (LLD-006 §3, LLD-007).

## Options Considered

### A. Static analysis only (chosen) vs. LLM-assisted classification vs. dynamic multi-state crawl
- **LLM classifies every conditional into a taxonomy:** rejected. Adds an ongoing model dependency to construction (conflicts with "reruns must be cheap and deterministic"), and — per the reasoning in Context — the classification isn't needed by the sole consumer, which can read raw expressions directly.
- **Dynamic crawl** (Crawljax-style: render the app under different auth/flag states, diff the DOM): rejected for v1. Requires a running, seeded instance of the target app per state permutation — expensive, environment-dependent, and orthogonal to the "cheap, deterministic, source-only" goal. Left as a possible future signal source, not part of this ADR.
- **Chosen — static analysis only, with a `needs_trace` escape hatch instead of forcing full resolution:** captures the large, reliable middle ground (in-file and one-hop-traceable conditions) deterministically, and is honest about the boundary instead of pretending indirected or runtime-only conditions are resolvable.

### B. Whole-graph `getMap` response (rejected) vs. route-scoped response (chosen)
- **Whole graph every call:** simplest contract, but defeats the purpose — an app large enough to need a KDG is large enough that its full graph is also too large to hand an agent on every authoring call.
- **Chosen — route-scoped by `entryUrl`:** keeps per-call cost bounded by one route's subgraph regardless of total app size. No widening parameter in v1 (kept out to keep the initial contract minimal); revisit only if a real cross-route authoring case demonstrates the need.

### C. Full rebuild on any change (rejected) vs. per-file incremental patch (chosen)
- **Full rebuild:** trivial correctness, but every single source change re-pays the full construction cost — directly contradicts "reruns must be cheap," which is the entire premise motivating this ADR.
- **Chosen — per-file node replacement keyed by a content-hash manifest:** bounds rebuild cost to files actually changed; git-diff-based staleness was considered and rejected because it breaks on uncommitted working-tree changes, which is exactly when a developer is actively iterating and rebuilding most often.

### D. Config-driven source scope (rejected for v1) vs. App Router convention (chosen)
- **Configurable glob:** more flexible (covers Pages Router, non-transitively-reached shared libraries), but requires the user to get the config right and risks over/under-scanning. Deferred as a future extension once the platform supports more than Next.js App Router.
- **Chosen — convention-based on `app/**`:** zero configuration, matches the framework's own structure, and is consistent with this ADR's Next.js-first scope decision.

## Consequences

- The KDG gains a real, buildable v1 construction algorithm; ADR-002's Action Item 8 is closed.
- No new runtime LLM dependency is introduced anywhere in construction — this stays true to ADR-001 as strictly as grounding/resolution do.
- v1 is explicitly Next.js App Router-only. Generic React (no framework routing convention), Vue, and Angular are out of scope until a future ADR revisits source-scope discovery for those ecosystems.
- `needs_trace` conditionals are not fully resolved by Gimbal — the agent must do a bounded, pointed follow-up read. This is a deliberate cost shifted to the agent in exchange for never fabricating a classification Gimbal cannot verify.
- The KDG has no independent existence outside `.gimbal/cache.db` — it is not git-versioned, not shared across machines by the repo, and is fully regenerable, exactly like the resolver's selector/embedding cache.
- `getMap`'s existing `{ entryUrl }` contract (LLD-008) is unchanged at the interface level; its response shape and route-scoping behavior are refined here and detailed in LLD-011.

## Out of Scope (deferred to later work)

- Non-Next.js frameworks and non-App-Router Next.js (Pages Router).
- Dynamic/multi-state crawling as a supplementary signal source for conditions static analysis marks `needs_trace` or `unknown`.
- A background file-watcher / daemon-maintained always-warm KDG (v1 is build-on-`getMap`-call only).
- Any widening parameter on `getMap` beyond single-route scoping.
- Using the KDG as an input to grounding or runtime resolution — this ADR scopes the KDG strictly to authoring-time and repair-payload context, unchanged from ADR-002.

## Design Principle

> The KDG tells an agent where the answer lives when it can't tell it the answer itself. Static analysis extracts everything it can verify; everything it can't is a pointer, never a guess.
